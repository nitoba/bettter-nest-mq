# Contributing

Install Bun 1.4.2 and a supported Node version, then run:

```sh
bun install --frozen-lockfile
bun run hooks:install
bun run check
```

The library is a single root package. Read README.md and docs/contracts.md for the current M1 surface; docs/roadmap.md distinguishes unimplemented engine/worker/storage features. Do not export simulated operations to make a planned API appear complete.

Run `bun run format` before committing. Oxlint/Oxfmt and the vendored plugin must retain the exact reviewed better-effect baseline; see docs/tooling.md. Changing a test fixture's contract is preferable to weakening a rule.

Tests cover unit behavior, real Nest contexts, compile-time inference and actual packed-package consumption. Add a failing regression before a behavior fix. Do not use module mocks for Nest or the engine.

Run `bun run build` before `bun run test:package` or `bun run publint` when invoking them individually. The full check builds automatically. External consumers live in temporary directories, compile with TypeScript 6/7, run under Node/Bun, and verify root consumption without Zod before installing the optional Zod integration.

New runtime dependencies need an implementation reason. Standard Schema is a public type dependency; Zod is an optional peer isolated behind the zod subpath. Database drivers must remain optional integrations. Keep dependency lockfiles generated by Bun rather than hand editing them.

The repository has no automatic npm publication. Releases require explicit authorization and a clean complete quality gate.
